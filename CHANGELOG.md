# Changelog

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow [SemVer](https://semver.org/).

## [1.0.0] - 2026-11-01

First public release. The app works the same as 0.11.2; this version marks the move to a public repository.

### Changed

- The repository is now public on GitHub, starting from a clean history; earlier development happened in a private repository, and its changes are summarized in the entries below
- From now on, every release uses a v1.x.y (or later) version
- README.md and README.zh-TW.md: added widget screenshots (`docs/images/`), and the first paragraph now says the app supports the Claude Desktop app

## [0.11.2] - 2026-10-31

### Changed (documentation only; app behavior unchanged)

- Project documents are now in English: `README.md` (the Traditional Chinese version moved to `README.zh-TW.md`, and each links to the other at the top), `CHANGELOG.md`, `CLAUDE.md`, `docs/algorithms.md` and the ADRs
- ADR files renamed to English: `0001-adopt-v1-ui.md`, `0002-use-pyside6.md`, `0003-layered-architecture.md`, `0004-i18n.md`, `0005-no-taskbar-embedding.md`
- Code comments, log messages and the `diagnose` output stay in Traditional Chinese for now; the app UI was already bilingual

## [0.11.1] - 2026-10-31

### Changed (documentation cleanup before making the repo public; app behavior unchanged)

- `CLAUDE.md` trimmed: the header keeps a single "matches app version" line instead of per-version change notes; the to-do list became "Feature overview" + "Possible future work"; every item in the old §7 "Open questions" now has a decision written into the relevant section (search all four desktop paths; no WSL / `weekly_scoped` / `spend`; a single tray icon; configurable shortcut; update check on by default), and the section was removed
- `docs/implementation-guide.md` (old pystray/tkinter-era examples) replaced by `docs/algorithms.md`: only token sources, desktop decryption, the Claude/Codex API formats, and error classification and scheduling remain, matching the current code
- Docs, ADRs and comments no longer mention personal names or design files outsiders can't see; wording updated for a public repo (the ubuntu + windows CI split is now justified by "pure-logic tests run faster"; the update-check 404 is described as "no Release yet or the API is temporarily unavailable")

## [0.11.0] - 2026-10-31

### Added

- Taskbar identity: `__main__.py` sets the AppUserModelID `kdwjzh.WindowsClaudeTracker` first thing (`platform/app_identity.py`; failures are only logged), so when run with pythonw the Settings window no longer shows the Python icon on the taskbar or gets grouped with other Python programs
- All windows now use `assets/app.ico` (the new segmented-grid design, 9 sizes from 16 to 256 px); the app falls back to the drawn icon only if the file can't be read. The tray icon is still drawn dynamically from usage
- `THIRD_PARTY_LICENSES.txt`: generated by `scripts/third_party_licenses.py` during `build.ps1`, listing the full licenses of the components bundled in the exe — Python, PySide6/Qt (LGPL-3.0 notice and where to get the source), requests, cryptography, truststore and others — plus the full LGPL-3.0/GPL-3.0 texts (`assets/licenses/`); attached to every Release
- Disclaimer: the README and the Settings "About" page now say "Unofficial tool, not affiliated with Anthropic or OpenAI. Claude, ChatGPT and Codex are trademarks of their respective owners." (Chinese and English)

### Changed

- `build.ps1`: bundles `assets/app.ico` into the app exe with `--add-data` so the packaged build can read it
- Removed `scripts/make_icon.py`: `assets/app.ico` is now provided by the maintainer and is never generated or overwritten by code
- Docs: CLAUDE.md revision 4 (removed the old stage 9 "taskbar embedding", added stage 10 "app icon and taskbar identity", marked completed stages); added ADR 0005 "No taskbar embedding"

## [0.10.0] - 2026-10-31

### Added (stage 8c: update check)

- `core/app_info.py`: the repo owner/name and URLs live only here; `core/semver.py`: version parsing and comparison (`1.10.0 > 1.9.0`, pre-releases don't count as newer, malformed versions never raise)
- `services/update_check.py`: queries `api.github.com/repos/kdwjzh/windows-claude-tracker/releases/latest` (no token); once 30 seconds after start, then every 24 hours; with automatic checks off, only manual checks run; 404/403/429/network errors show "Can't check right now" without a notification; only accepts Release URLs from this repo; notifies once per new version; a version can be skipped
- Tray: when a new version is available, a blue `#7fb3ff` dot at the bottom right of the icon and a "New version vX →" item at the top of the menu; clicking the notification opens the Release page (auth-error notifications still run diagnostics)
- Settings "About" page: version + "Check for updates", status text, "Download", automatic-check switch, "Skip this version", project page, license
- All new text is available in Traditional Chinese and English

### Changed

- Settings `schema_version` 1 → 2: added `update_check` (`enabled` on by default, `skipped_version`, `last_checked_at`, `notified_version`); old settings are migrated automatically
- `TrayVM` gained `update_dot`; `ui/bridge.py` gained the `update_changed` signal; added `platform/launch.open_url()` (https only)
- Adopted the MIT license: added `LICENSE`, `license` in `pyproject.toml`, a "License" section in the README; the Settings "About" page shows `MIT`

## [0.9.0] - 2026-10-30

### Added (stage 8a: local packaging)

- `scripts/build.ps1`: PyInstaller builds `dist\ClaudeUsageTracker.exe` (`--noconsole --onefile`, unused Qt modules excluded, about 50 MB) and `dist\diagnose.exe` (with a console, no Qt, about 14 MB); runs `check.ps1` first by default (`-SkipCheck` skips it)
- `scripts/version_info.py`: the exe file version info (Properties → Details) comes from `__version__`
- `assets/app.ico` and `scripts/make_icon.py`: the app icon reuses the tray icon design, each size (16–256 px) drawn as vectors; the Settings window uses it too
- `README.md`: install, update, uninstall, data sources and privacy, settings fields, troubleshooting, development and release steps

### Added (stage 8b: automated releases)

- `.github/workflows/release.yml`: after a `vX.Y.Z` tag is pushed, on `windows-latest`: verify the tag matches `__version__` (fail if not) → run `check.ps1` → build → generate `SHA256SUMS.txt` → create a GitHub Release with `ClaudeUsageTracker-vX.Y.Z.exe`, `diagnose-vX.Y.Z.exe` and `SHA256SUMS.txt`; notes come from the matching section of this file; tags containing `-` are marked as pre-releases
- `scripts/release_notes.py`: verifies the tag, extracts release notes, detects pre-releases (with tests; the current `__version__` must have a section in this file)

### Fixed

- CI had been failing since stage 0: the ubuntu job passed `-p no:pytestqt` to disable pytest-qt, but the plugin name is `pytest-qt`, so Qt still loaded and crashed on ubuntu without libEGL; changed to `-p no:pytest-qt`
- 6 Qt tests assumed a Chinese UI and failed on English Windows (the GitHub Actions runner): `tests/ui/conftest.py` now makes all Qt tests assume English Windows, and tests that need Chinese set `language: "zh-TW"` themselves; `ui/controller.system_ui_languages()` became its own function so it can be pinned

### Changed

- `ci.yml` runs only on branch pushes and PRs; tags are left to `release.yml` to avoid running twice
- In the packaged build, "Run diagnostics" looks for `diagnose.exe` in the same folder, and otherwise for the newest `diagnose-vX.Y.Z.exe` downloaded from Releases
- `ui/tray/icon.render_pixmap()` gained a `size` parameter so it can draw any size

## [0.8.0] - 2026-10-30

### Added (stage 7: CLI token refresh, off by default)

- `platform/cli_refresh.py`: `ClaudeCliRefresher` finds `claude.cmd`/`claude` (`.cmd` runs through `cmd.exe /d /c`), checks `--version` ≥ 2.0.63, then runs `claude -p . --no-session-persistence` so the CLI refreshes with its own refresh token; this app never touches the refresh token
  - `CREATE_NO_WINDOW` and timeouts (15 seconds for the version check, 90 seconds for the refresh); the working directory is a temp folder
  - At least 30 minutes between attempts; the version check result is remembered, and a too-old CLI is not tried again
- `ClaudeProvider.configure_cli_refresh()`: refreshes only when **no usable token exists and the CLI token has merely expired**, then re-reads the file; never runs while a desktop token is usable (to avoid wasting quota)
- The `allow_cli_refresh` setting can be toggled at any time and applies immediately; the Settings hint text was updated

## [0.7.1] - 2026-10-30

## [0.6.0] - 2026-10-29

### Added (stage 6: Settings window)

- `ui/settings_dialog/`: a Windows 11-style Settings window (design artboard 5) with "General / Advanced / About" navigation on the left; dark/light follows the widget theme
  - General: refresh interval, start with Windows, show widget, lock position, opacity slider, auto-hide in full screen, show/hide shortcut (press "Change", then the new combination; a failed registration is reported), theme, per-service switches and connection status

## [0.3.0] - 2026-10-29

### Added (stage 3: services)

- `services/logging_setup.py`: RotatingFileHandler (1 MB × 2); a masking filter on the handler masks `sk-ant-…`, `Bearer …` and JWTs in messages, arguments and tracebacks
- `services/settings/`: `Settings` (with `schema_version`), lenient per-field validation (a bad field falls back to its default and is logged), version migration (v0 → v1), atomic writes, change notifications; a malformed file is saved as `settings.json.broken` instead of being overwritten; files from a newer version are read but never written
- `services/state_store.py`, `services/subscribers.py`: hold each service's `ProviderState` and notify subscribers; one failing subscriber doesn't affect the others
- `services/scheduler.py`: independent scheduling and backoff per service (`30s × 2^(n-1)`, capped at the interval, the larger of that and `Retry-After`); pauses on auth errors and compares the credential signature every 60 seconds; keeps old data marked `stale` on failure; schedules an early poll at `resets_at + 10 seconds`; any exception affects only that service

### Notes

- Settings gained `widget.theme` (`system` / `dark` / `light`) for the "Theme" option in design artboard 5

## [0.2.0] - 2026-10-29

### Added (stage 2: diagnostics)

- `python -m usage_monitor.diagnose`: walks through the CLI credentials, each desktop candidate folder (files, token cache, DPAPI, each entry's scopes / masked token / expiry, with `→` marking the token that will be used), the moved-data markers in old paths and the actual API result, then lists where it got stuck and how to fix it
- `--no-api`: check token sources only; `--poll claude`: call the API only
- Output contains only masked tokens (first 14 + last 4 characters; short ones are fully masked), and token cache keys show only the scopes, never the install or account IDs
